Six Checks Your Trainer Won't Run

Each one either crashes the run or quietly trains the wrong thing.

All rules →

  • Schema

    Malformed JSONL, missing fields, wrong types. The one rule you can't disable.

    schemaerror

  • Role Order

    Doubled turns, misplaced system prompts, conversations that end on the user.

    roleserror

  • Empty Content

    Blank or whitespace-only turns that teach the model silence.

    empty-contenterrorfixable

  • Duplicates

    Repeated records that push the model toward memorizing instead of generalizing.

    duplicateserrorfixable

  • Context Window

    Records over your token budget, which TRL truncates without telling you.

    context-windowerrorfixable

  • Encoding

    BOM markers and mojibake that end up baked into the weights.

    encodingwarningfixable

Check. Fix. Gate.

Every issue gets a line and a rule. Mechanical problems are repaired, the rest are dropped with a reason, and the re-check decides.

  1. 01 · checkparallelogram check data.jsonl

    Every issue with its line number and rule. Exits 0, 1 or 2.

  2. 02 · fixparallelogram check data.jsonl --fix --output clean.jsonl

    Mechanical repairs, then a re-check. Anything still broken is dropped, with the reason.

  3. 03 · gateuses: Thatayotlhe04/Parallelogram@v1

    The GitHub Action fails the pull request when dataset quality regresses.

Frequently Asked Questions

Questions? We've got answers.

or read the docs →
What does "exits 0" actually guarantee?

With all rules on: every record parses, has a valid role order ending on the assistant, has no empty turns or exact duplicates, and fits your token budget (counted exactly with --tokenizer, estimated otherwise). It checks that your data will train, not that it's good data.

Does my data leave my machine?

No. Nothing is uploaded and there is no telemetry. The only network request is opt-in: --tokenizer may download a tokenizer vocabulary once, then caches it.

Which formats are supported?

OpenAI/Qwen chat JSONL, ShareGPT and prompt/completion, detected per line. --fix writes each record back in the shape it came in.

Are token counts exact?

With pip install 'parallelogram[tokenizer]' and --tokenizer, yes (tiktoken or Hugging Face). Without, counts are estimated and overflows are warnings, never errors.

How do I use it in CI?

Add uses: Thatayotlhe04/Parallelogram@v1 to a workflow. It writes a report to the job summary and fails on errors, or on regressions against a --baseline.

Is it free?

Yes. Apache-2.0, on PyPI and GitHub.
