Catch fine-tuning dataset bugs before they poison training.

Parallelogram is an open-source CLI that validates OpenAI chat JSONL and ShareGPT datasets — broken role sequences, empty messages, duplicates, encoding artifacts, context-window overflows — locally, before the training run.

02 · Silent failure modes

Your dataset can be broken without looking broken.

Bad JSONL doesn't always crash the trainer. It trains anyway — on poisoned data. Eight failure modes Parallelogram catches:

Broken role alternation

{"role":"user","content":"Try again."},
{"role":"user","content":"Hello? Anyone?"}

Alternation is the supervision signal — doubled turns teach the model that user messages answer user messages.

[roles] ERROR

Empty assistant messages

{"role":"user","content":"Explain RoPE."},
{"role":"assistant","content":"   "}

A whitespace-only target slips past most loaders and trains the model that silence is a valid completion.

[empty-content] ERROR

Exact duplicates

line  89: {"messages":[…]}   # hash 9f31c2…
line 147: {"messages":[…]}   # hash 9f31c2…

Repeated records push the model toward memorization and quietly inflate any eval that samples the same file.

[duplicates] ERROR

Invalid JSONL

{"messages":[{"role":"user","content":"ok"}
            # unterminated — not JSON

One truncated line either fails the whole ingest or gets skipped silently — which one depends on the loader, not on you.

[schema] ERROR

Mojibake / encoding artifacts

"content":"Donâ€™t merge yet"
           # UTF-8 → latin-1 → UTF-8

Round-trip artifacts look almost right in an editor and bake corrupted punctuation directly into the weights.

[encoding] WARNING

Context-window overflow

record 131:  5234 tokens
max_seq_len: 4096 tokens

TRL truncates oversized records without a word — usually severing the assistant turn you were training on.

[context-window] ERROR

Format drift (OpenAI chat vs ShareGPT)

{"messages":[{"role":"user", …}]}
{"conversations":[{"from":"human", …}]}

A ShareGPT record in an OpenAI-chat file isn't almost right — it's a different schema. Parallelogram refuses to guess per record.

[schema] ERROR normalized at the parse boundary

Conversation ends on user

{"role":"assistant","content":"Done."},
{"role":"user","content":"thanks!!"}

The final turn is the training target. Ending on a user message means there is no target at all — just wasted loss.

[roles] ERROR

03 · Architecture

One parser boundary. Every rule runs on the same representation.

Raw formats are normalized once, at parse time. Downstream, the structural checks, the tokenizer-aware context checks, and the safe fixer all operate on a single internal message shape — no rule ever special-cases a format.

Click a stage to inspect it. Formats normalize at the parse boundary — every rule runs on one internal message representation.

05 · Checks

Checks built for fine-tuning data, not generic JSON.

A JSON schema validator can tell you a record is well-formed. It can't tell you the conversation ends on the wrong speaker, repeats itself, or won't fit the model's context window.

06 · Tokenizers

Context-window checks with exact tokenizers when possible.

When an exact tokenizer is available — tiktoken for OpenAI models, Hugging Face tokenizers for open-weight models — overflow is a hard ERROR. Otherwise Parallelogram falls back to a ~4 chars/token estimate and reports a WARNING. A heuristic never deletes records or fails CI. Claude models have no offline tokenizer, so they always use the estimate.

07 · Formats

Normalize formats once. Run every rule unchanged.

Two formats ship today. Both collapse to the same internal message list at the parse boundary, and --output writes survivors back in the shape they came in.

OpenAI chat --format openai-chat · default

↓ normalized

ShareGPT --format sharegpt

{"conversations":[{"from":"human","value":"…"}]}

↓ normalized

09 · Quickstart

Install. Point it at a dataset. Read the diagnostics.

No config file, no account, no network. Python ≥ 3.10.

# install — the extras add exact tokenizers (tiktoken + HF)
$ pip install parallelogram
$ pip install 'parallelogram[tokenizer]'
# validate — openai-chat is the default format
$ parallelogram check data.jsonl
# ShareGPT datasets — every rule runs identically
$ parallelogram check data.jsonl --format sharegpt
# repair what's mechanical, drop what isn't — with reasons
$ parallelogram check data.jsonl --fix --output clean.jsonl
# exact token counts against a budget
$ parallelogram check data.jsonl --tokenizer gpt-4o --max-seq-len 4096

10 · Use cases

Run it wherever a dataset meets a trainer.

One command between your raw data and anything that consumes it.

Before OpenAI fine-tuning

Validate the JSONL before you upload it to the OpenAI fine-tuning API — catch rejections and silent quality issues before the job is queued.

Before Axolotl / TRL / Unsloth runs

Axolotl, TRL, and Unsloth assume your data is clean. None of them verify it. Run the preflight before the GPU bill starts.

Cleaning ShareGPT datasets

Public ShareGPT dumps are full of duplicates, broken turn orders, and mojibake. --format sharegpt --fix writes the survivors back in ShareGPT shape.

Checking synthetic instruction data

Generation pipelines drift: empty completions, repeated samples, truncated records. Validate the output before it contaminates a training mix.

CI gate for dataset PRs

Exit codes 0/1/2 map directly to CI status with no extra wiring. A dataset PR that breaks role order fails the same way a code PR with a failing test does.

Preflight for SLM training data

Small models are less forgiving of dirty data, and small-model runs repeat often. Make the structural check a fixed step, not a vibe check.
